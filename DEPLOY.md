# Размещение приложения ПБК на сервере: GitHub + Render

Инструкция составлена уже по вашему реальному коду (`package.json`, `index.ts`, `storage.ts`, `pbkdb.ts`, `pbkload.ts`, `static.ts`). Стек: Express 5 + Vite 7 + React 18 + better-sqlite3 + Drizzle.

---

## Что я нашёл в коде и что уже исправил

При проверке обнаружились четыре места, из-за которых деплой либо не заработал бы вообще, либо терял данные. Все правки уже готовы в приложенных файлах.

| Проблема | Где | Почему критично |
|---|---|---|
| Сервер слушает `host: "127.0.0.1"` | `server/index.ts`, строка 99 | Render не смог бы «дозвониться» до приложения — вы получили бы ошибку `Application failed to respond`. Заменено на `0.0.0.0` |
| База жёстко привязана к `data.db` в корне | `server/storage.ts`, строка 19 | Файл лежал бы во временной папке контейнера и обнулялся при каждом обновлении кода |
| Вторая база на тот же файл | `server/pbkdb.ts`, строка 7 | Модуль ПБК открывает `data.db` отдельно — путь нужно было менять в двух местах |
| Загруженные файлы сводок в `pbk_files` | `server/pbkload.ts`, строка 14 | Все загруженные Excel-файлы ПБК пропадали бы при обновлении |

Решение — новый файл `server/paths.ts`, единая точка настройки. Локально всё работает как раньше, на сервере переменная `DATA_DIR=/var/data` переводит базу и файлы на постоянный диск.

## Готовые файлы

Замените в проекте на приложенные:

- `server/paths.ts` — **новый файл**, создать
- `server/index.ts` — исправлен хост
- `server/storage.ts` — путь к базе через `DB_PATH`
- `server/pbkdb.ts` — то же для модуля ПБК
- `server/pbkload.ts` — папка файлов через `FILES_DIR`
- `render.yaml` — в корень проекта, настройки сервиса и диска
- `script/load_staff.mjs` — путь к базе был жёстко прописан как `/home/user/workspace/grr-control/data.db`, теперь берётся из `DB_PATH`
- `.gitignore` — в корень проекта

## Часть 1. Установка Git

1. Скачайте Git для Windows: [git-scm.com/download/win](https://git-scm.com/download/win)
2. Запустите установщик, во всех окнах жмите **Next** — настройки по умолчанию подходят
3. Проверьте: откройте VS Code, терминал (`Ctrl` + `` ` ``), введите `git --version`. Должно появиться `git version 2.xx.x`

Если пишет «команда не найдена» — закройте и заново откройте VS Code.

## Часть 2. Регистрация на GitHub

1. Откройте [github.com/signup](https://github.com/signup)
2. Введите email, пароль, имя пользователя латиницей (например `pbk-grr`)
3. Подтвердите email по письму

## Часть 3. Создание репозитория

1. Откройте [github.com/new](https://github.com/new)
2. Заполните:
   - **Repository name**: `pbk-control`
   - Обязательно **Private** — в коде названия объектов, заказчиков и цены за метр
   - Галочки «Add a README», «Add .gitignore», «Choose a license» — **не ставить**
3. **Create repository**
4. Скопируйте адрес вида `https://github.com/ваше-имя/pbk-control.git`

## Часть 4. Загрузка проекта на GitHub

Сначала положите в корень проекта приложенный `.gitignore` — он не даст загрузить `node_modules`, базу `data.db` и папку `pbk_files` с рабочими файлами.

Затем в терминале VS Code, находясь в папке проекта, выполните команды **по одной**:

```
git init
git add .
git commit -m "Первая версия приложения ПБК"
git branch -M main
git remote add origin https://github.com/ваше-имя/pbk-control.git
git push -u origin main
```

Вместо `ваше-имя` подставьте свой логин.

При первом `git push` откроется браузер с просьбой войти в GitHub — войдите и нажмите **Authorize**. Обычный пароль GitHub в терминале больше не принимает, только вход через браузер.

Если Git попросит указать имя и почту, выполните один раз:

```
git config --global user.name "Ваше Имя"
git config --global user.email "ваша@почта.ru"
```

### Проверка перед отправкой

Сборка на сервере упадёт, если в репозиторий не попадёт что-то из этого списка. Перед `git push` выполните:

```
git ls-files script vite.config.ts tsconfig.json tailwind.config.ts postcss.config.js
```

Должны перечислиться все файлы. Критичнее всего `tsconfig.json`: в коде сервера используются импорты вида `@shared/schema`, а `esbuild` разбирает эти псевдонимы только через `paths` в `tsconfig.json` — без этого файла сборка сервера остановится на `Could not resolve "@shared/schema"`.

Также проверьте папки: `git ls-files client shared | head`. Если где-то в клиенте используется алиас `@assets`, папка `attached_assets` тоже должна быть в репозитории.

Скрипт сборки `script/build.ts` к деплою готов, править его не нужно: `esbuild` подставляет `NODE_ENV=production` в код на этапе сборки, поэтому ветка с dev-режимом Vite вырезается из `dist/index.cjs`, и `vite.ts` на сервере не задействуется вообще — вместе с его жёстким `process.exit(1)` при ошибке сборки.

Питоновские скрипты (`test_templates.py`, `test_fromfile.py`, `make_icons.py`) на сервере не запускаются и никак ему не мешают — можно спокойно загружать вместе с остальным кодом.

## Часть 5. Регистрация на Render

1. Откройте [dashboard.render.com/register](https://dashboard.render.com/register)
2. Нажмите **GitHub** — аккаунты свяжутся сразу, отдельный пароль не нужен
3. При запросе доступа выберите **Only select repositories** и укажите `pbk-control`

## Часть 6. Создание сервиса через Blueprint

Раз в проекте есть `render.yaml`, все настройки подхватятся автоматически — это надёжнее ручного заполнения полей.

1. В панели Render нажмите **New** → **Blueprint**
2. Выберите репозиторий `pbk-control` → **Connect**
3. Render покажет, что создаст: web-сервис `pbk-control`, тариф Starter, диск `pbk-data` 1 ГБ на `/var/data`
4. Нажмите **Apply** и подтвердите платный тариф
5. Сборка занимает 5–10 минут (`better-sqlite3` компилируется под сервер). В логах должно появиться `Your service is live`

### Если предпочитаете вручную

**New** → **Web Service** → репозиторий `pbk-control`, затем:

| Поле | Значение |
|---|---|
| Name | `pbk-control` |
| Region | `Frankfurt (EU Central)` — ближайший к Красноярску |
| Branch | `main` |
| Runtime | `Node` |
| Build Command | `npm install && npm run build` |
| Start Command | `npm start` |
| Instance Type | **Starter — $7/month** (не Free) |

Переменные окружения (блок **Environment Variables**):

| Key | Value |
|---|---|
| `NODE_VERSION` | `20` |
| `DATA_DIR` | `/var/data` |
| `NPM_CONFIG_PRODUCTION` | `false` |
| `SESSION_SECRET` | длинная случайная строка |

Диск (**Advanced** → **Disks** → **Add Disk**):

| Поле | Значение |
|---|---|
| Name | `pbk-data` |
| Mount Path | `/var/data` |
| Size (GB) | `1` |

### Почему нельзя ставить NODE_ENV=production

Это самая частая ошибка при таком деплое. Если добавить переменную `NODE_ENV=production`, то `npm install` пропустит `devDependencies` — а у вас там `tsx`, `vite`, `esbuild`, `typescript`, то есть всё, чем собирается проект. Сборка упадёт с ошибкой «tsx: not found».

Ставить эту переменную и не нужно: ваш скрипт `start` уже сам задаёт `NODE_ENV=production` при запуске. Переменная `NPM_CONFIG_PRODUCTION=false` добавлена как страховка.

## Часть 7. Первый вход и пользователи

1. Откройте адрес сервиса — показан сверху страницы сервиса, вида `https://pbk-control.onrender.com`
2. Войдите под учётной записью директора
3. **Сразу смените пароль** — приложение теперь доступно из интернета
4. Раздел «Пользователи» → создайте логины остальным трём сотрудникам, каждому свою роль (аналитик, геолог, лаборант, снабженец, наблюдатель)
5. Загрузите файлы сводок через раздел ПБК — они лягут на постоянный диск в `/var/data/pbk_files`

База при первом запуске создастся пустой и заполнится демо-данными через `seedDatabase`. Рабочие данные переносите импортом Excel — как делаете это локально.

## Часть 8. Как обновлять приложение потом

После правок кода в VS Code:

```
git add .
git commit -m "Описание что изменил"
git push
```

Render увидит изменения и пересоберёт приложение за несколько минут. Данные на диске не теряются. Учтите: при обновлении сервис на минуту становится недоступен — диск не позволяет деплой без простоя ([Render Docs](https://render.com/docs/disks.md)).

## Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| `tsx: not found` или `vite: not found` при сборке | Задана переменная `NODE_ENV=production` — удалите её из настроек сервиса |
| `Application failed to respond` | Не применена правка `index.ts` с `host: "0.0.0.0"` |
| `Could not find the build directory` | В репозиторий не попала папка `script/` или `vite.config.ts` |
| `Could not resolve "@shared/schema"` | Не загружен `tsconfig.json` — без его `paths` псевдонимы не работают |
| Данные пропали после обновления | Не задана `DATA_DIR=/var/data` или неверный Mount Path диска |
| Ошибка компиляции `better-sqlite3` | Задайте `NODE_VERSION=20` — на новых версиях Node сборка native-модуля иногда падает |
| `git push` требует пароль | Вход только через браузер, обычный пароль GitHub не принимается |

При любой ошибке скопируйте текст из логов Render (страница сервиса → **Logs**) и пришлите мне — разберу.

## Резервные копии

Диск надёжен, но копии всё равно нужны. Раз в неделю выгружайте данные встроенным экспортом в Excel — он есть у каждого раздела — и храните файлы у себя. Отдельно копируйте загруженные файлы сводок ПБК: они хранятся только на сервере, если удалить их локально.

## Позже, если приложение вырастет

Постоянный диск привязывает сервис к одному экземпляру — масштабировать на несколько серверов нельзя ([Render Docs](https://render.com/docs/disks.md)). Для 4 человек это никак не мешает. Если когда-нибудь пользователей станет 20–30 и понадобится резервирование, тогда есть смысл переходить с SQLite на PostgreSQL — переписывать придётся только `storage.ts` и `pbkdb.ts`, остальной код останется.
