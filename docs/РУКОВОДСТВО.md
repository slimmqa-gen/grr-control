# ГРР-Контроль: полное руководство

Для кого: для вас, без опыта программирования.
Что внутри: как устроена программа, что менять самому в окне программы, как обслуживать сервер, как вносить правки в код так же, как это делал я, и как настроены боты, почта и копии.

Правило документа: одна команда — один шаг. Перед каждой командой написано, где её выполнять:

- **Локальный PowerShell** — окно PowerShell на вашем компьютере.
- **Linux-сервер по SSH** — окно, где вы уже подключились к серверу (часть 3, шаг 1).

## Часть 1. Как всё устроено

| Что | Где | Зачем |
|---|---|---|
| Программа | сайт https://24pbk.ru | Вы и сотрудники работаете в браузере |
| Сервер | VPS Timeweb, IP 147.45.215.116 | Круглосуточно держит программу, базу, почту, бота |
| Папка программы | `/opt/pbk-control` на сервере | Код и собранная программа |
| Данные | `/var/pbk-data` на сервере | База `data.db`, сводки, архив писем, заявки |
| Резервные копии | `/var/pbk-backups` на сервере + облако (если настроено) | Каждую ночь в 03:30 |
| Служба | `pbk-control` | Сама запускает программу при старте сервера |
| Код | GitHub, репозиторий `slimmqa-gen/grr-control`, ветка `main` | Отсюда сервер берёт обновления |
| Бот MAX | бот `id2463233969_bot` («PBK») | Вызовы, сводки, кнопки, переписка |
| Почта | ящик Mail.ru | Отсюда программа забирает сводки участков |
| СМС | SMSC.ru | Запасной канал, если у человека нет MAX |

Как проходит изменение: правка кода → отправка в GitHub (`main`) → на сервере `update.sh` забирает код, собирает и перезапускает. База и файлы при этом не трогаются, а перед обновлением делается копия.

## Часть 2. Что можно менять самому прямо в программе (без кода)

Всё ниже делается мышкой, под учётной записью директора.

### Разделы меню
- ☐ «Настройки» → «Разделы программы»: добавить, скрыть, переименовать, поменять порядок.

### Справочники (пункт меню «Справочники»)
- ☐ Объекты (участки): план метров, цена, штат.
- ☐ Буровые станки: участок или «Не назначен на участок», статус. Загрузка сводок ручной участок станка не стирает.
- ☐ Автомобили: марка, госномер, назначение (водовозка, бензовоз…), участок, статус, примечание.
- ☐ Должности, техника для ГСМ, статьи затрат, ТМЦ, лаборатории, виды анализов.

### Пользователи и права
- ☐ Пункт меню «Пользователи»: создать логин, выбрать роль, привязать к участкам, отключить.
- ☐ Сразу смените стандартные пароли у analyst, geolog, lab, supply, viewer — у них пароль совпадает с логином.
- ☐ После 5 неверных паролей вход по логину закрывается на 15 минут. Если заблокировали себя — подождите или перезапустите службу (часть 3, шаг 6).

### Сотрудники и вахты
- ☐ Карточка сотрудника: должность, участок или «Не назначен на участок», телефон, метод работы (вахта, офис, ПП).
- ☐ Назначить вахту: даты заезда и выезда, выезд можно отметить «не определена».
- ☐ Правка дат: карандаш во вкладке «Вахты» или «Архив вахт».
- ☐ «Предварительный заезд»:
  - «Кто свободен» на дату, с фильтром по должности;
  - план с участком, станком или машиной;
  - «Кого меняет» — сама, вручную или «никого не меняет»;
  - «Подтвердить» — вахта назначается сама;
  - «План в Excel» и «Назначенные вахты в Excel».
- ☐ Отсутствия: отпуск, больничный, командировка, обучение.

### Суточная сводка («Реальные данные ПБК»)
- ☐ «Почта»: ящик, пароль приложения, адреса отправителей, частота проверки, «Забрать почту сейчас», «Забрать заново».
- ☐ «Суточная сводка»: получатели в MAX, у каждого — свои участки («все участки ▾»), окно утренней рассылки.
- ☐ Архив редакций: просмотр и удаление (корзина).
- ☐ «Сводки»: ручная загрузка файла, удаление файла.
- ☐ «Заявки на материалы»: файлы с «заявк» в названии, скачивание.

### Бот MAX («Сотрудники и вахты» → «Настройка уведомлений»)
- ☐ Ответственные — кому приходят отказы, напоминания о вызовах и «кто где».
- ☐ Голубой блок «Кнопки в MAX по ролям»:
  - директор;
  - буровые мастера;
  - кому из мастеров открыта сводка на межвахте;
  - напоминания о заезде;
  - утренний отчёт директору;
  - «Разослать меню всем».
- ☐ Жёлтый блок «Кто видит личную переписку»: до 4 человек в MAX и логины в программе. Открывает только директор.
- ☐ «Состояние системы»: «Проверить бота», «Прислать отчёт директору сейчас».
- ☐ «Вызов на вахту»: кого пора вызвать, отправка кнопкой. Время напоминания ответственным («Во сколько напоминать, час») — в «Настройке уведомлений», блок СМС.

## Часть 3. Обслуживание сервера

### Шаг 1. Подключиться к серверу
Локальный PowerShell:
```
ssh root@147.45.215.116
```
Спросит пароль сервера — это пароль root из панели Timeweb. При вводе символы не видны, это нормально. После входа строка начинается с `root@pbk-control`. Все команды с пометкой «Linux-сервер по SSH» вводите здесь.

### Шаг 2. Установить обновление программы
Linux-сервер по SSH:
```
cd /opt/pbk-control && sudo bash deploy/update.sh
```
В конце должно быть «ГОТОВО. Версия … работает». Скрипт сам делает копию базы, собирает программу и при неудаче возвращает прежнюю сборку.

### Шаг 3. Проверить без изменений, всё ли готово к обновлению
Linux-сервер по SSH:
```
cd /opt/pbk-control && bash deploy/update.sh --dry-run
```

### Шаг 4. Состояние службы
Linux-сервер по SSH:
```
systemctl status pbk-control --no-pager
```
`active (running)` — работает. Выход — клавиша `q`.

### Шаг 5. Журнал программы (последние 50 строк)
Linux-сервер по SSH:
```
journalctl -u pbk-control -n 50 --no-pager
```
Смотреть в реальном времени — `journalctl -u pbk-control -f`, выход `Ctrl+C`.

### Шаг 6. Перезапустить программу
Linux-сервер по SSH:
```
sudo systemctl restart pbk-control
```

### Шаг 7. Проверка почты, сводки и бота одним отчётом
Linux-сервер по SSH:
```
cd /opt/pbk-control && sudo bash deploy/diag.sh
```
Ничего не меняет, пароли не показывает. Показывает: настройки почты, вход в ящик, последние письма, журнал, файлы сводок, по какой день данные, рассылку, ошибки.

### Шаг 8. Сделать резервную копию сейчас
Linux-сервер по SSH:
```
cd /opt/pbk-control && sudo bash deploy/backup.sh
```

### Шаг 9. Настроить копии в облако (один раз)
Linux-сервер по SSH:
```
cd /opt/pbk-control && sudo bash deploy/backup-cloud.sh
```
Выберите Яндекс Диск или Облако Mail.ru, введите логин и **пароль приложения**:
- Яндекс: id.yandex.ru → Безопасность → Пароли приложений → «Файлы»;
- Mail.ru: пароль для внешнего приложения с доступом к Облаку.

Пароль хранится только на сервере, в `/etc/pbk-backup.env`.

### Шаг 10. Посмотреть список копий
Linux-сервер по SSH:
```
ls -lh /var/pbk-backups | tail -20
```

### Шаг 11. Место на диске
Linux-сервер по SSH:
```
df -h /
```
Если занято больше 85%, напишите мне или удалите старые копии из `/var/pbk-backups`.

### Восстановить базу из копии (только если база испорчена)
Делайте по шагам, не пропуская.

1. Linux-сервер по SSH — остановить программу:
   ```
   sudo systemctl stop pbk-control
   ```
2. Linux-сервер по SSH — сохранить текущую базу на всякий случай:
   ```
   cp /var/pbk-data/data.db /var/pbk-data/data.db.before-restore
   ```
3. Linux-сервер по SSH — найти нужную копию (имя вида `data_2026-09-30_03-30.db.gz`):
   ```
   ls -1t /var/pbk-backups/data_*.db* | head
   ```
4. Linux-сервер по SSH — распаковать копию на место базы (подставьте своё имя файла):
   ```
   gunzip -c /var/pbk-backups/data_2026-09-30_03-30.db.gz > /var/pbk-data/data.db
   ```
5. Linux-сервер по SSH — убрать служебные файлы старой базы:
   ```
   rm -f /var/pbk-data/data.db-wal /var/pbk-data/data.db-shm
   ```
6. Linux-сервер по SSH — запустить программу:
   ```
   sudo systemctl start pbk-control
   ```

Старые копии без `.gz` в конце распаковывать не нужно: в шаге 4 вместо `gunzip -c … >` используйте `cp имя_копии /var/pbk-data/data.db`.

## Часть 4. Как вносить правки в код самому (как это делаю я)

### 4.1. Один раз подготовить компьютер
- ☐ Установить **Node.js 20 LTS**: nodejs.org → LTS → установщик, везде «Next».
- ☐ Установить **Git**: git-scm.com/download/win, везде «Next».
- ☐ Установить **VS Code**: code.visualstudio.com.
- ☐ Иметь доступ к GitHub-репозиторию `slimmqa-gen/grr-control`.

Проверка — Локальный PowerShell:
```
node -v
```
Должно быть `v20…`. Затем — Локальный PowerShell:
```
git --version
```

### 4.2. Скачать проект (один раз)
Локальный PowerShell — перейти в папку «Документы»:
```
cd $HOME\Documents
```
Локальный PowerShell — скачать проект (при первом разе откроется окно входа в GitHub):
```
git clone https://github.com/slimmqa-gen/grr-control.git
```
Локальный PowerShell — войти в папку проекта:
```
cd grr-control
```
Локальный PowerShell — поставить библиотеки (3–5 минут):
```
npm install
```

### 4.3. Каждый раз перед работой — забрать свежий код
Локальный PowerShell (в папке `grr-control`):
```
git pull
```

### 4.4. Запустить программу у себя на компьютере
Локальный PowerShell:
```
npm run dev
```
Откройте в браузере http://localhost:5000 и войдите: логин `director`, пароль `director`. Это **ваша тестовая копия** с учебными данными. Рабочую базу она не трогает, можно ломать что угодно. Остановить — `Ctrl+C` в окне PowerShell.

### 4.5. Где что лежит

| Хочу поменять | Файл |
|---|---|
| Сотрудники, вахты, настройки MAX на экране | `client/src/pages/crew.tsx` |
| Предварительный заезд | `client/src/pages/crew-plan.tsx` |
| Суточная сводка, почта, сводки, заявки | `client/src/pages/pbk-daily.tsx` |
| Справочники (станки, автомобили…) | `client/src/pages/references.tsx` |
| Тексты и кнопки бота MAX | `server/max.ts`, `server/maxmenu.ts` |
| Текст суточной сводки для MAX | `server/daily.ts` (`summaryHtml`) |
| Утренний отчёт директору, проверка бота, напоминания о заезде | `server/automation.ts` |
| Вызовы на вахту, СМС | `server/sms.ts` |
| Сбор почты | `server/mail.ts` |
| Разбор Excel-сводок | `server/pbkparse.ts` |
| Права ролей | `shared/schema.ts` (`ROLES`), `server/auth.ts` |
| Правило статуса (на вахте, межвахта…) | `shared/status.ts` |
| Скрипты сервера | папка `deploy/` |

Поиск по всем файлам в VS Code: `Ctrl+Shift+F`, введите текст, который видите на экране, например «Кто свободен». Так вы сразу найдёте нужное место.

### 4.6. Пример: поменять надпись на кнопке
1. VS Code → «File» → «Open Folder» → папка `grr-control`.
2. `Ctrl+Shift+F`, найдите текст кнопки, например `Подтвердить выбранных`.
3. Исправьте текст внутри кавычек или между `>` и `<`. Ничего вокруг не трогайте.
4. `Ctrl+S` — сохранить. Если запущен `npm run dev`, экран обновится сам.

### 4.7. Проверить, что ничего не сломали
Локальный PowerShell — проверка кода (ответа нет — всё хорошо):
```
npm run check
```
Локальный PowerShell — пробная сборка (в конце должно быть `Done`):
```
npm run build
```
Если есть ошибки — не отправляйте. Верните правку (`Ctrl+Z` в файле) или пришлите текст ошибки мне.

### 4.8. Отправить правку в GitHub
Локальный PowerShell — посмотреть, какие файлы изменены:
```
git status
```
Локальный PowerShell — подготовить все изменения:
```
git add -A
```
Локальный PowerShell — записать изменение с понятным описанием:
```
git commit -m "Изменил надпись на кнопке подтверждения"
```
Локальный PowerShell — отправить в GitHub:
```
git push
```

### 4.9. Установить на сервер
Linux-сервер по SSH:
```
cd /opt/pbk-control && sudo bash deploy/update.sh
```

### 4.10. Если правка оказалась неудачной — отменить последнюю
Локальный PowerShell — создать отменяющее изменение:
```
git revert HEAD --no-edit
```
Локальный PowerShell — отправить:
```
git push
```
Затем на сервере — шаг 4.9. Так история не теряется, а программа возвращается к прежнему виду.

### 4.11. Правила, чтобы не потерять данные
- ☐ Код меняете только у себя и отправляете через GitHub. На сервере файлы руками не правите: `update.sh` откажется обновляться, если в папке есть «чужие» изменения.
- ☐ Папку `/var/pbk-data` не трогаете — там рабочая база.
- ☐ Перед крупной правкой сделайте копию (часть 3, шаг 8).
- ☐ Пароли, токены и ключи в код не пишете — они вводятся в окне программы и лежат в базе.

### 4.12. Как я работал и как можно поступать так же
1. Понять, что нужно, и найти место в коде поиском по тексту с экрана.
2. Сделать правку.
3. Запустить у себя (`npm run dev`) и проверить руками на тестовых данных.
4. `npm run check` и `npm run build`.
5. `git add -A`, `git commit`, `git push`.
6. На сервере — `update.sh`.
7. Проверить на https://24pbk.ru.

Большие изменения удобнее поручать ИИ-помощнику, но на тех же шагах. Самое важное — шаги 3 и 4: они ловят ошибки до того, как их увидят люди.

## Часть 5. Бот MAX: как он настроен

### 5.1. Как появился бот
1. Бота может создать только организация или ИП. Для этого нужен профиль на платформе «MAX для партнёров», подтверждённый через Госуслуги ([MAX для бизнеса](https://dev.max.ru/help/miniapp-main), [Albato](https://blog.albato.ru/kak-nastroit-bota-v-max-polnyj-gajd-bez-programmirovaniya/)).
2. На платформе: «Чат-боты» → создать бота → имя и ник.
3. Токен бота: «Чат-боты» → «⋮» → «Настройки» ([документация MAX](https://dev.max.ru/docs-api)). Токен — это пароль бота, никому его не присылайте.
4. В программе: «Сотрудники и вахты» → «Настройка уведомлений» → «Имя бота» и «Токен бота» → «Сохранить».

### 5.2. Как бот получает сообщения
- Режим **webhook**. MAX сам присылает события на адрес `https://24pbk.ru/api/max/webhook` с секретным ключом. Чужие запросы без ключа отклоняются.
- Включается в «Настройке уведомлений»: поле «Адрес для событий» (`https://24pbk.ru/api/max/webhook`) → кнопка «Включить webhook». Адрес — только `https://…`, без порта. Кнопка «Вернуть опрос» — запасной режим без webhook.
- Раз в час программа проверяет, что подписка на месте. Если она пропала, восстанавливает её сама и пишет директору.
- Если что-то не так — «Проверить бота» в блоке «Состояние системы».

### 5.3. Как сотрудник подключается к боту
1. «Сотрудники и вахты» → «Настройка уведомлений» → таблица персональных ссылок → «Копировать» у нужного человека.
2. Отправьте ссылку человеку (СМС, WhatsApp, лично).
3. Человек открывает ссылку и нажимает «Начать». Профиль привязан, приходят кнопки.
4. Кто не привязан, ничего не получает, а его сообщения никуда не пересылаются.

### 5.4. Кто что видит в боте

| Роль | Кнопки |
|---|---|
| Директор | Кто где · Сводка · Заезды · Смена вахт · Вызовы · События · Люди |
| Ответственные | Кто где · Сводка · Заезды · Вызовы · События |
| Буровые мастера | Сводка (только на вахте или с разрешения) · Смена вахт своего участка · Мой заезд · Написать сообщение |
| Сотрудники | Мой заезд · Написать сообщение |

- Меню вызывается словом **«меню»**.
- В групповых чатах бот не работает.

### 5.5. Что бот делает сам и что только по кнопке

| Сам, по расписанию | Только кнопкой |
|---|---|
| Проверка почты (15 мин — 2 ч) | **Вызов на вахту** сотруднику |
| Утренняя сводка получателям и мастерам на вахте | «Разослать меню всем» |
| Сообщение об изменениях сводки | «Прислать отчёт директору сейчас» |
| Напоминание ответственным: кому пора отправить вызов | «Забрать почту сейчас» |
| Утренний отчёт директору в 9:30 | |
| Напоминание о заезде за 3 и 1 день — только тем, кому вызов уже отправлен | |
| Сообщение сотруднику о переносе или отмене вахты — только после вызова | |
| Проверка бота раз в час | |

### 5.6. Личная переписка
- Сообщения сотрудников с текстом получают только до 4 человек, которых отметил директор.
- В программе раздел «Переписка» видят директор и те логины, которым он его открыл.
- Отказы от заезда и их причины приходят всем ответственным — это рабочая информация.

### 5.7. Если бот молчит — по порядку
- ☐ «Проверить бота». Если красное — прочитайте причину.
- ☐ Человек привязан? Посмотрите в таблице ссылок.
- ☐ Человек в нужной роли? Проверьте голубой блок.
- ☐ Служба работает? Часть 3, шаг 4.
- ☐ Журнал: часть 3, шаг 5, ищите строки со словом `MAX`.
- ☐ Токен заменили на платформе MAX? Вставьте новый в настройки и снова включите webhook.

## Часть 6. Почта со сводками

1. В Mail.ru: Настройки → Безопасность → «Пароли для внешних приложений» → создать пароль с доступом к IMAP. Обычный пароль не подойдёт.
2. В программе: «Реальные данные ПБК» → «Почта»:
   - сервер `imap.mail.ru`, порт `993`;
   - папка `INBOX`;
   - «Смотреть письма за» — 3 дня;
   - адреса отправителей — по одному в строке, можно `@домен`;
   - частота проверки;
   - «Сохранить».
3. Сразу после сохранения программа забирает почту. На «Суточной сводке» цветная строка показывает, работает ли почта и по какой день есть данные по каждому участку.
4. Удалённый на вкладке «Сводки» файл снова заберётся с почты при следующей проверке. Чтобы обновить сводку, удалять файл не нужно: новое письмо само заменит старое.
5. Если в жёлтом блоке есть «письма от адресов вне списка» — нажмите «Добавить в список».

## Часть 7. СМС (запасной канал)
- «Сотрудники и вахты» → «Настройка уведомлений» → блок СМС (SMSC): логин и пароль SMSC вводите сами в программе, в чат не присылайте.
- Если человек привязан к MAX, вызов уходит в MAX бесплатно. Если нет — СМС на номер из карточки.

## Часть 8. Безопасность — короткий список
- ☐ Сменить стандартные пароли у всех логинов, ненужные отключить.
- ☐ Пароль директора знаете только вы.
- ☐ Токен бота, пароль почты, пароль SMSC, пароль облака — никому не пересылать.
- ☐ Настроить копии в облако (часть 3, шаг 9) и раз в месяц смотреть в утреннем отчёте «Копия выгружена в облако».
- ☐ Доступ «Наблюдатель заказчика» — только чтение и без кадровых разделов.

## Часть 9. Быстрые ответы

| Ситуация | Что делать |
|---|---|
| Суточная сводка пустая | Цветная строка над сводкой → причина. Затем «Забрать почту сейчас» |
| Сводка участка «устарела» | В письме более старые данные, чем в программе, — это защита. Проверьте файл у мастера |
| Сотрудник пишет, что не пришёл вызов | «Вызов на вахту»: вызов отправлен? Человек привязан к MAX? |
| Не могу войти | После 5 ошибок подождите 15 минут или перезапустите службу (часть 3, шаг 6) |
| Программа не открывается | Часть 3, шаг 4, затем шаг 5, затем шаг 6 |
| После обновления что-то сломалось | Часть 4.10 (отменить правку) или пришлите вывод `update.sh` |
| Нужно понять, что происходит с почтой и ботом | Часть 3, шаг 7 — пришлите вывод |


## Предварительный выезд

Раздел «Сотрудники и вахты» → «Предварительный заезд и выезд» → переключатель «Выезд».

- [ ] Авто: если в плане заезда указано «кого меняет», сменяемый сам появляется в выезде — дата = день заезда сменщика.
- [ ] Вручную: «Запланировать выезд вручную» → дата → отметить людей на вахте → «Сохранить». Ручная дата перекрывает авто.
- [ ] Карандаш — изменить дату, стрелка — вернуть авто-дату, корзина — убрать из плана.
- [ ] «Подтвердить» / «Подтвердить выбранных» / «Подтвердить всех на участке» — дата выезда встаёт в настоящую вахту.
- [ ] «Выезд в Excel» — список по участкам.
- [ ] В MAX кнопка «🗓 Предв. заезд и выезд»: директор и ответственные видят все участки, мастер — свой. Директор подтверждает заезд и выезд по участку прямо из MAX.
